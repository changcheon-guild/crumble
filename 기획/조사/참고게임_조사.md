# 참고 게임 조사: 모네타 아카데미 · ECLIPSE 전야

- 조사일: 2026-11-01
- 대상: <https://moneta-academy.com/>, <https://eclipse-eve.rladmstj1228.chatgpt.site/>
- 목적: 우리 게임(하늘 군도 원정 방치형 RPG)을 두 게임의 복제로 만들려는 것이 아니다. 구조·화면 구성·UX·기술 방식에서 배울 점을 찾는다.
- 방법: 공개 HTML, 연결된 JS·CSS 번들, manifest, 서비스 워커, 로그인 없이 응답하는 공개 API만 받아서 읽었다. 받은 스크립트는 실행하지 않았다. 로그인하지 않았고, 봇 차단 우회(User-Agent 위장 등)도 하지 않았다. 두 사이트 모두 일반 요청에 정상 응답했고 차단은 없었다.
- 표기
  - **[확인]**: 공개 페이지, 공개 API 응답, 번들 코드의 상수·문구에서 직접 본 것.

  - **[미확인]**: 이번 조사로 알 수 없었던 것.
- 두 게임 모두 **초대 코드가 있어야 가입**할 수 있다. 그래서 로그인 뒤 내용은 거의 모두 [코드 추정]이다. 모네타는 규칙 엔진(`shared/rules.js`)과 데이터(`shared/data.js`)를 주석까지 그대로 배포해서 수치를 많이 확인할 수 있었다. 이클립스는 압축된 React 번들이라 화면 문구와 일부 상수만 확인했다.

**원정** [확인]

- 10단계마다 관문 보스가 있다(`isBoss: s % 10 === 0`). 지역 하나가 10단계이고, 지역마다 몬스터 3종과 보스 1종이 있다(예: 지하 저장고 1단계~, 속삭이는 숲 11단계~, 침몰한 천문대 21단계~, 수정 동굴 31단계~).
- 갈 수 있는 단계의 상한은 학년이 정한다(학년×10+9). 레벨이 높으면 상한을 10단계까지 더 넘을 수 있다. 레벨이 상한보다 5 넘게 높으면 경험치가 줄어든다.
- **출발 전 미리보기**: 예상 처치 수 · 아르크 · 경험치와 함께 위험도(처치 한 번에 받는 피해 ÷ 최대 생명력)를 **안정(≤0.25) · 적정(≤0.5) · 위험(≤1) · 무모함(>1)** 네 단어로 보여 준다.
- 위험도가 1을 넘으면 출발할 때 쓰러질 시각이 정해지고, 그때까지 모은 것의 80%를 받는다. 직접 취소하면 50%를 받는다.
- `bestStage`: 1시간 기준 (아르크 + 경험치×0.5)가 가장 큰 단계를 추천한다.
- 31단계부터 몬스터 공격이 단계마다 +8%(최대 2.2배) 세진다. 주석: "40단계쯤이면 지원 포지션이 필요할 만큼".

**함께 원정(파티)** [확인]

- 최대 4명. 포지션은 선봉 · 후열 · 지원 셋이다.
  - 선봉: 몬스터가 80% 확률로 노린다(기사 수호 성향과 일부 주문으로 최대 95%). 방어 +25%.
  - 후열: 공격 주문을 장착해야 고를 수 있다. 공격 +10%, 받는 피해 +10%.
  - 지원: 치유·보호막 주문을 장착해야 고를 수 있다. 공격 −15%, 파티가 받는 피해 −15%(여럿이면 최대 −30%).
- 처치 수는 인원수로 나누지만 1명 늘 때마다 +5%를 더 준다. 사람 파티원 1명당 아르크 +3%, 경험치 +1%(최대 3명분). 전리품은 각자 따로 굴린다.
- 혼자 먼저 귀환하면 모은 것의 50%만 받는다. 30분 안에 3번 그러면 3시간 동안 함께 원정에 참가할 수 없다.
- **NPC 친구**: 사람이 적을 때 빈자리를 채운다. 방장 힘의 60%로 싸우고, 파티 보너스와 보상 대상에는 들지 않는다.

**별의 탑(파티 탑)** [확인]

- 파티 단위로 하루 1번 실전을 한다. 마지막으로 넘은 층이 이번 주 기록이 되고, 월요일 0시(KST)에 초기화된다. 연습은 언제나 할 수 있고 기록·보상이 없다.

### 1-4. 기술 스택

- [확인] **프레임워크 없는 순수 JavaScript**다. 빌드 도구의 흔적도 없다. 파일이 나뉜 그대로 배포된다: `app.js`(약 1.97MB), `shared/data.js`(0.79MB), `shared/rules.js`(0.61MB), `draw.js`, `sound.js`, `net.js`, `style.css`(0.27MB). 각 파일이 IIFE로 전역(`DATA`, `Rules`, `Art`, `Net`)을 만든다.
- [확인] **서버·클라이언트 공용 규칙 엔진**이다. `rules.js`가 `module.exports`(Node)와 브라우저 전역을 함께 지원한다. 머리 주석: "서버가 권위를 가진다: 클라이언트는 같은 코드로 미리보기만 계산한다." 모든 시간은 초 단위 유닉스 시각이다.
- [확인] 그림은 `draw.js`에서 절차적으로 그린다(몬스터 · 캐릭터 · 사역마 · 문장 · 하늘. 해시 시드 기반). 효과음은 `sound.js`가 음원 파일 없이 Web Audio로 합성하고, 설정에서 켤 때만 난다.
- [확인] API
  - REST JSON이다. 행동은 대부분 **`POST /api/act {type, a}` 단일 엔드포인트**로 보낸다. 조회는 `/api/state`, `/api/world`, `/api/market/*`, `/api/tower` 등이고, 약 75개 경로를 확인했다.
  - 인증은 HttpOnly 쿠키로만 한다. 주석: "스크립트가 토큰을 읽거나 저장하지 않음".
  - 가입·로그인이 몰려 서버가 503(busy)을 주면 3~6초 간격으로 최대 약 3분 동안 다시 보낸다. 점검 중이면 503과 함께 점검 정보를 받는다.

- 아르바이트는 NPC 납품 의뢰다. 투명 핵과 채집 경험치를 주고, NPC마다 짧은 이야기가 붙는다.

**장비 · 아이템** [확인]

- 부위: 무기(블레이드 · 지팡이 · 권총/소총) · 의류 · 악세사리. 재질 이름은 나무 · 구리 · 철 · 오리하르콘 · 아다만티움.
- 레벨대별 상점 장비가 있고, 능력치는 고정 수치다(예: "공격력 +4", "최대 체력 +15 · 방어력 +1").
- [코드 추정] 희귀도 표기는 노멀 · 유니크 · 레어 · 스페셜 레어. 어디에 붙는지는 확인하지 못했다.
- 편의 아이템: 스탯 초기화권, 이름 변경권, 길드 확장권(+5명, 2회), 능력 변환석, 역할 변환석. "외모" 능력치를 올리는 장비도 있다.

**거래(장터 게시판)** [확인]

- 투명 핵으로 거래한다. 판매를 등록하면 물품을 따로 보관하고, 취소하거나 수량을 줄이면 가방으로 돌아온다. 구매한 물품은 **우편함**으로 온다.
- 장착 중인 장비와 계정 귀속 물품은 팔 수 없다. 캐릭터당 판매글 수에 상한이 있다.

- 통신이 실패하면 "같은 거래 번호로 재확인하며, 중복 구매·차감을 방지합니다."
- [미확인] 수수료가 있는지는 문구에서 찾지 못했다.

**길드** [확인] 15레벨부터 만들 수 있고 비용은 없다. 가입 방식은 자유 가입 또는 승인제다. 확장권으로 최대 30명까지 늘린다. 길드장 · 부길드장, 위임 · 퇴출 · 해산, 길드 채팅(RP와 사담 구분).

### 2-4. 기술 스택

- [확인] **React 19.2.6**(framework 청크의 버전 문자열).
- [확인] **vinext**: Next.js App Router와 호환되는 Vite 기반 RSC 런타임. 응답 헤더 `Vary`에 `X-Vinext-*`가 있고, `vite-rsc/importer-resources`, `vinext.navigationRuntime`이 보인다. 청크 경로는 `/_next/static/`이다. 번들러 흔적은 `rolldown-runtime-*.js`다.
- [확인] Cloudflare 앞단(`server: cloudflare`, `__cf_bm` 쿠키, `/cdn-cgi/challenge-platform` 스크립트 삽입). 도메인은 `*.chatgpt.site`의 하위 도메인이다. [미확인] 이 도메인의 호스팅 주체와 구조는 확인하지 않았다.
- [확인] API: 같은 앱의 Route Handler(`/api/world`, `/api/world/live`, `/api/market`, `/api/party-finder`, `/api/party-chat`, `/api/typing`, `/api/gathering`, `/api/guilds`, `/api/messages`, `/api/halloween`, `/api/rankings`, `/api/admin/*` 등). 응답은 JSON이다.
- [확인] **실시간 통신 없음**: 번들에 WebSocket · EventSource · socket.io 같은 흔적이 없다. 5초 · 10초 · 15초 간격의 `setInterval`이 보이고, 화면 문구에 "5초마다 새로 확인", "N초마다 새 대화 확인"이 있다. 폴링으로 갱신하는 구조로 보인다. `/api/typing`(입력 중 표시)도 폴링으로 보인다.
- [확인] 상태 저장: 서버에 둔다("모든 선택은 서버에 저장됩니다. 다른 기기에서도 이어갈 수 있어요"). `localStorage`에는 테마 · 알림음 · 상단 상태 접힘만 넣는다. manifest와 서비스 워커는 없다(manifest 404). 푸시 알림 흔적도 없다.
- [확인] 아이콘은 lucide(SVG). 알림음은 AudioContext로 낸다. 프로필 사진과 길드 로고는 업로드할 수 있다(긴 변 1,024px로 저장).

## 6. 확인하지 못한 것

- **로그인 뒤 실제 화면**: 두 게임 모두 초대 코드가 필요해 들어가지 않았다. 화면 배치·연출·실제 수치는 모두 코드에서 추정했다. 특히 이클립스는 압축 번들이라 화면 구조를 문구 위주로만 알 수 있다.
- **서버 쪽 구현**: 모네타의 서버 언어·DB, 이클립스의 DB·저장 방식은 공개 범위에서 알 수 없다. 모네타는 `rules.js`가 Node `module.exports`를 지원하는 것으로 미루어 Node 서버로 추정할 뿐이다.
- **모네타 상태 갱신 주기**: 주석 "최대 2분"만 확인했고, 실제 간격은 확인하지 못했다.
- **모네타 전설 보정**(`LEG_PITY = 600`, `LEG_RAMP = 250`)의 단위와 정확한 동작.
- **이클립스 장터 수수료** 여부, 희귀도(노멀~스페셜 레어)가 적용되는 대상, 에너지의 시간당 자연 회복량.
- **이클립스 `chatgpt.site` 도메인의 호스팅 형태**: Cloudflare 앞단과 vinext 런타임까지만 확인했다.
- **두 게임의 이용자 수·잔존율·평가**: 모네타 `/api/meta`의 기숙사별 인원(합계 1,292)만 확인했다. 활성 이용자인지는 알 수 없다.
